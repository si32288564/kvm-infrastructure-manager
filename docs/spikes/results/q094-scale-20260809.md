# Q-094 1,000-session Scale Result — 2026-08-09

- 状態: Preliminary / Non-certifying
- Host: Apple M2 / darwin arm64
- Go: 1.26.5
- Session 数: 1,000
- Open/echo concurrency: 100
- Transport security: TLS 1.3 mutual authentication
- 対象: gRPC bidirectional stream、typed protobuf stream over HTTP/2

## Fixture Correction

比較前に、両 adapter の `Receive()` 呼出しごとの goroutine 生成を除去しました。各 connection は一つの persistent receive loop を持ち、`Receive(ctx)` は結果 channel と caller context だけを待ちます。

共通 contract test は次を確認します。

- 100 回連続の caller timeout で goroutine 数が線形増加しない
- caller timeout は transport session を cancel しない
- timeout 後も同一 session で typed Envelope を送受信できる
- connection loss は deadline より前に transport uncertainty として返る

typed HTTP/2 adapter は、一つの transport が一つの Agent session generation だけを所有するため `DisableKeepAlives` を設定しました。旧 generation の connection を新 generation へ再利用せず、`Close()` は receive loop 終了後に idle connection を閉じます。これがない場合、旧 1,000 connection が 5 秒以内に drain せず、新 generation と一時的に重複することを fixture が検出しました。

## Method

候補ごとに別 process で次を実行しました。

```sh
go run ./cmd/kim-agent-transport-scale -candidate grpc -sessions 1000 -concurrency 100
go run ./cmd/kim-agent-transport-scale -candidate http2 -sessions 1000 -concurrency 100
```

各 run は次を行います。

1. generation 1 の 1,000 mTLS session を最大 100 並列で確立する。
2. 全 session で一つの Result Envelope を concurrent echo し、latency を集計する。
3. GC 後の goroutine、Go heap、FD を記録する。
4. generation 1 を全て close し、active connection が 0 へ drain したことを確認する。
5. generation 2 の 1,000 session を再確立し、全 session の echo を検証する。

この fixture は一 process 内に Agent client と echo Gateway server の両方を持つため、FD と goroutine は両端の合計です。reconnect は全 session の同時 close と bounded parallel reopen であり、Gateway admission、jitter、backoff、DB session registry contention はまだ含みません。

## Result

| Metric | gRPC bidi | typed HTTP/2 |
|---|---:|---:|
| generation 1 open | 257.6 ms | 220.8 ms |
| close/drain + generation 2 reopen | 309.9 ms | 231.6 ms |
| echo p50 | 1.110 ms | 0.578 ms |
| echo p95 | 2.343 ms | 1.301 ms |
| echo p99 | 3.362 ms | 1.610 ms |
| goroutine at 1,000 idle sessions | 11,002 | 6,002 |
| heap alloc at idle | 123.3 MB | 75.8 MB |
| heap reserved at idle | 167.4 MB | 120.6 MB |
| open FD at idle | 2,010 | 2,010 |
| old generation drained before reopen | yes | yes |
| accepted physical connections after reconnect | 2,000 | 2,000 |
| active physical connections after reconnect | 1,000 | 1,000 |

これは単一 run の non-certifying result です。CPU、RSS、network impairment、proxy、bulk saturation、slow consumer、durable spool、Gateway processing、PostgreSQL authority を含まず、候補の production capacity を示しません。

## Interpretation

per-message goroutine churn を除去した条件では、typed HTTP/2 がこの concurrent fixture で少ない goroutine/heap と低い echo latency を示しました。初回の単一 session loopback では gRPC が低い latency を示しており、現時点で性能上の一方的優位はありません。

現時点の位置付けは、gRPC が **operational/control-path leader**、typed HTTP/2 が **density leader** です。単一の provisional leader は置きません。10,000-session までの resource curve は [Q-094 Session Density Curve](q094-session-density-curve-20260809.md)、slow-reader/HOL 特性は [Q-094 Bulk Saturation Result](q094-bulk-saturation-20260809.md) で追跡します。

## Decision Status

`HOLD`です。少なくとも次を完了するまで Q-094 を Close しません。

- bulk Inventory/Resync saturation 中の Control/Lease/Result p99 と bounded bulk service
- Gateway admission/backoff を含む reconnect storm
- old/new credential overlap と session generation handoff
- Envoy/HAProxy 等の supported proxy/LB behavior
- durable spool、response loss、Gateway restart、resync convergence
- 10,000-session extrapolationまたは分散 fixture
- CPU/RSS、dependency/SBOM、security update surface の比較
